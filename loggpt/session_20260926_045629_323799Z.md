## What was done this session

1. **PNG start-menu labels located (they are images, not text).**
   Byte search over the built APK proved `开始游戏`, `快速进入` and `快速注册`
   exist in no dex/arsc/`Language*.str` entry. OCR of every image entry in the
   installed APK found the real labels: `login/botton1..6.png` (normal 155x44)
   and `login/botton11..16.png` (bright 189x59) =
   开始游戏 / 快速进入 / 快速注册 / 退出游戏 / 修复游戏 / 联网选择, selected in
   `AuthenticateCommon` (`imgBottonImage`, `imgBrightBottonImage`).
   `sysui/t_m_menu_*.png` hold the same labels but are not what the running
   start menu draws; `mm4.png`/`mm5.png` are 608x15 decoration strips with no
   readable text.

2. **New pixel translator** `build/english_test/translate_menu_labels.py`:
   colour-classifies glyph vs. decorative swirl (fill/edge rules), erases the
   dilated glyph mask while keeping swirl pixels, then draws Arial Bold with a
   stroke in the sampled label colours (cream/maroon normal, gold/red bright).
   All 12 buttons translated; OCR confirms `Start Game`, `Quick Enter`,
   `Quick Register`, `Exit Game`, `Repair Game`, `Network Select`.

3. **PNG colour-type finding (VERIFIED by A/B rebuild on the real client).**
   Writing the labels as RGBA (colour type 6) made the client block forever on
   `读取中...100%`; re-saving the identical art as palette PNG (colour type 3,
   per-index `tRNS`, matching the source) loads normally. The translator now
   always emits palette PNG via `quantize(colors=256, method=FASTOCTREE)`.

4. **Message batch added to the map** (341 pairs total in
   `build/english_test/build_en_ui.py`): login/auth validation, loading and
   confirmation strings (`请输入用户名和密码` → `Please enter a username and
   password`, `读取中...` → `Loading...`, `账号不能为空`, `0.返回`, server status
   labels, etc.). `verify_en_ui.py` reports
   `mapping entries still present in Chinese: 0`; `MainMenu`/`AuthenticateCommon`
   have 0 Chinese literals (4 deferred `RoleLogin` class descriptions remain).

5. **Tool made bilingual** (`tools/truthan_ui_control.py`):
   `LABEL_ALIASES` + `label_matches()` (space-insensitive, Chinese + English),
   English `classify()` branches built from a space-free reading-order
   concatenation so detector-split labels still classify (`START_MENU`,
   `ACCOUNT_LOGIN`, `ROLE_LIST`, `CREATE_ROLE`, `NAME_INPUT`, `NETWORK_ERROR`),
   and a leading-token fallback in `target()`. Chinese OCR behaviour unchanged.
   Focused suite after every change: `py -m unittest tests.test_truthan_ui_control
   tests.test_v026_baseline tests.test_map_entry_integration` → **50 tests OK**.

6. **Build/install/launch.** apktool 3.0.3 (Java 8) → `zipalign -f 4` →
   `apksigner` → `adb install -r`. Installed as `com.t4game.en` (label
   `TruThan EN`, versionCode 215) **alongside** `com.t4game`; nothing uninstalled
   or cleared. Two real problems fixed with evidence: `INSTALL_FAILED_
   DUPLICATE_PERMISSION` (removed the redundant getui `<permission>` element)
   and `SecurityException: getDeviceId` on first launch
   (`adb shell pm grant com.t4game.en android.permission.READ_PHONE_STATE`).
